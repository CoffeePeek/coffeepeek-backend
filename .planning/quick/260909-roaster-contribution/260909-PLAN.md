<objective>
Implement `.planning/specs/ROASTER-CONTRIBUTION.md`: expand `Roaster` from a name-only catalog tag into a full profile (geocoded address, Instagram/website contact, photos, about), add a user submission → moderation queue → admin approve/reject → publish-into-Shops pipeline mirroring `ModerationShop`, extend admin CRUD to the same fields, and add a public `GET /api/roasters/{id}` detail endpoint (with linked shops) served by the Shops service.

Key architectural finding from scouting (not in the spec, discovered while planning): Moderation and Shops are separate databases with no synchronous link today. The spec's duplicate-name check (Requirement 2, "409 on duplicate submission") needs Moderation to ask Shops "does an approved roaster with this name exist?" at submit time. Precedent exists: `CoffeePeek.Shops.Infrastructure/Account/AccountUserExistenceLookup.cs` + `services.AddHttpClient("account-user-lookup", ...)` in `CoffeePeek.Shops.Infrastructure/DependencyInjection.cs` is Shops calling Account the same way. This plan adds the mirror: Moderation calling Shops' existing public `GET /api/catalogs/roasters` endpoint — no new endpoint needed for the lookup itself.
</objective>
