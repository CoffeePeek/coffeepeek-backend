<objective>
Fix the real 404: clients read reviews from Shops (`/api/users/{id}/reviews`, shops-generated PKs) then PUT `/api/ModerationReviews/{id}` using that id, but the moderation DB has unrelated PKs so GetById returns null. Root cause: on approval, `ModerationReviewApprovedHandler` mints a NEW Guid via `Review.Create(...)` and never links the two rows.

This plan (Variant B) links every published shops `Review` to its source `ModerationReview` via a new `ModerationReviewId`, and routes user edits through **re-moderation**: editing a review sets the moderation review back to Pending and HIDES the published shops review (reusing the existing `IsSoftDelete` flag) until a moderator re-approves.

Purpose: eliminate the 404, make edits safe (nothing unmoderated goes public), keep the two databases correctly correlated.
Output: contract link field + two new events, moderation edit-to-Pending flow, shops domain/persistence link + migration, rewritten/added shops consumers, one-time backfill, tests.
</objective>
