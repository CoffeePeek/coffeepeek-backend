<objective>
Allow any authenticated user to submit a section-specific change request for an existing coffee
shop. Moderators/admins can review and edit the proposal, then approve or reject it. Approval
publishes an idempotent cross-service event and applies the approved section to the published shop.
</objective>

<decisions>
- One request changes exactly one section: photos, contacts, description, tags, roasters,
  equipment, menu (including menu photos), or brew methods.
- Store the versioned typed payload as jsonb in the Moderation database so the queue remains
  extensible without a sparse table for every section.
- Gallery/menu photo proposals contain retained published photo IDs plus newly uploaded media
  metadata, allowing add/remove/reorder without re-uploading retained photos.
- Only authenticated users can submit. Moderator/Admin policy protects queue, edit, and decision
  endpoints. Submitters can list and read their own requests.
- Approval is immutable and emits at most one event. The Shops consumer records the applied request
  ID to make RabbitMQ redelivery idempotent.
</decisions>
