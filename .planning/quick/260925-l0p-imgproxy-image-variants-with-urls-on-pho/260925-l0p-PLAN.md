<imgproxy_facts>
<!-- Verified against docs.imgproxy.net (Context7 /websites/imgproxy_net + WebFetch) during planning. -->
- IMGPROXY_PRESETS: presets separated by commas; options inside one preset separated by `/`. Example from the docs: `default=resizing_type:fill/enlarge:1,sharp=sharpen:0.7`.
  So `thumb=rs:fill:240:180,card=rs:fill:600:450,detail=rs:fit:1200:1200,full=rs:fit:1920:1920` is valid.
- `enlarge` defaults to false, so `rs:fit` never upscales small originals.
- Presets-only mode (IMGPROXY_ONLY_PRESETS=true): the processing-options segment holds only preset names, colon-separated. The docs example is `/unsafe/thumbnail:blurry:watermarked/plain/...`. A single preset is `/_/card/plain/...`.
- Signature: "If the signature check is disabled (no key/salt pairs are provided), the signature part may contain
  anything (for example, `unsafe` or `_`)". So `_` is accepted.
- `plain/` source: imgproxy expects it percent-escaped, at minimum `%`→%25, `?`→%3F and `@`→%40 (`@` marks the output extension).
- IMGPROXY_BASE_URL is a prefix added to each source URL, so `plain/coffeepeek.shops/shops/x.jpg` becomes `http://minio:9000/coffeepeek.shops/shops/x.jpg`.
  IMGPROXY_ALLOWED_SOURCES is a whitelist of source URL prefixes.
- IMGPROXY_TTL sets Cache-Control max-age (the default is already 31536000). IMGPROXY_BIND defaults to `:8080`.
- IMGPROXY_AUTO_WEBP / IMGPROXY_AUTO_AVIF pick the output format from the Accept header when no extension is given.
</imgproxy_facts>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Internet → Caddy (MEDIA_DOMAIN/img/*) → imgproxy | Untrusted URLs choose the preset and source path |
| imgproxy → MinIO (internal HTTP) | imgproxy fetches source objects anonymously |
| Config/env → MediaPublicUrlOptions | Operator-supplied endpoint is echoed into every API response |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-l0p-01 | Denial of Service | imgproxy (arbitrary resize/processing params → CPU/memory exhaustion) | mitigate | IMGPROXY_ONLY_PRESETS="true" allows only the 4 fixed presets; `rs:fit` never enlarges (enlarge=false default); container memory limited to 512M |
| T-l0p-02 | Information Disclosure / SSRF | imgproxy source fetching | mitigate | IMGPROXY_BASE_URL=http://minio:9000/ prefixes every source and IMGPROXY_ALLOWED_SOURCES=http://minio:9000/ whitelists only MinIO; imgproxy publishes no host port and is reachable only through Caddy /img/* |
| T-l0p-03 | Information Disclosure | MinIO buckets exposed via imgproxy | accept | imgproxy has no MinIO credentials, so it can only read anonymous-download buckets (coffeepeek.shops, coffeepeek.avatars) that MEDIA_DOMAIN already serves publicly — no new exposure |
| T-l0p-04 | Tampering | BuildVariantUrl path construction (`@`/`?`/`%` in storage keys altering imgproxy parsing) | mitigate | Each bucket/key segment is Uri.EscapeDataString-escaped; unit test asserts `@`→%40, `?`→%3F, space→%20 |
| T-l0p-05 | Tampering | Misconfigured ImageProxyEndpoint echoed into responses | mitigate | OptionalHttpUrlAttribute rejects non-http(s)/relative values at startup (ValidateDataAnnotations + ValidateOnStart); empty = safe fallback to PublicEndpoint |
| T-l0p-06 | Spoofing | Unsigned imgproxy URLs | accept | Only 4 presets over already-public images; signing adds no confidentiality. Presets-only mode (T-l0p-01) covers the abuse vector signing would address |
| T-l0p-SC | Tampering | Container image supply chain (ghcr.io/imgproxy/imgproxy:latest) | accept | Official imgproxy organisation image, `:latest` by locked user decision (same policy as quay.io/minio/minio:latest already in the stack). No npm/pip/cargo installs, so the package-legitimacy gate does not apply |
