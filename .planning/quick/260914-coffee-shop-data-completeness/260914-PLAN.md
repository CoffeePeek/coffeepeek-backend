<objective>
Add a persisted 0-100 coffee-shop data completeness score, backfill it for all existing shops,
keep it current whenever contributing data changes, expose it in public shop DTOs, and rank public
shop search results by completeness descending with name as a stable tie-breaker.
</objective>

<decisions>
- Store `DataCompletenessScore` as a small integer on `Shops`; never calculate it in read queries.
- Weights total 100: gallery photo 15, menu 15, published review 10, schedule 15,
  coffee details 20 (roaster/brew method/bean/equipment: 5 each), contacts 15
  (Instagram/phone/site: 5 each), check-in 10.
- Menu counts as present when it has at least one item or menu photo. Soft-deleted reviews do not count.
- PostgreSQL trigger functions are the canonical recalculation mechanism because contributing rows
  belong to several aggregates/tables and may be changed by multiple application workflows.
- Add `(Status, DataCompletenessScore DESC, Name)` index for the public active-shop query.
</decisions>
