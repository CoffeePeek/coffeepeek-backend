<objective>
Fix the production 400 `VALIDATION_FAILED` on `POST /api/ModerationReviews`. The live client at
https://api.coffeepeek.by posts a flat body — `ratingCoffee`, `ratingPlace`, `ratingService` as
top-level int fields — but `SendReviewToModerationCommand` currently declares a required nested
`RatingDto Rating` constructor parameter. Since there's no in-repo client (CoffeePeek is
backend-only per CLAUDE.md), System.Text.Json can't populate the nested `Rating` object from the
flat payload, and ASP.NET Core's implicit-required-on-non-nullable-reference-type model binding
rejects the request before the handler ever runs — the client never sends a `rating` object at
all, so `Rating` stays unbound and required-validation trips before any handler code executes.

Purpose: Unblock the live client's review-submission flow without touching the shared
`CoffeePeek.Contract.Dtos.RatingDto` (used by other working endpoints — `CreateCheckInCommand`,
`UpdateCoffeeShopReviewCommand`, `GetAllModerationReviews`, etc.) and without changing any other
endpoint.

Output: `SendReviewToModerationCommand` accepts both the flat top-level shape (what the live
client actually sends) and the legacy nested `rating` object (backward compatible, e.g. for the
internal `CheckInCreatedHandler` consumer which constructs the command directly in C# with a full
`RatingDto`), resolved through a single `EffectiveRating` property that the validation strategy
and handler read from. A regression test proves the flat shape deserializes and validates
successfully.
</objective>
