<objective>
Add the Account-local user profile address registry and its lifecycle. This plan creates the typed `UserPublicAddress` registry with a generated migration, and a SaveChanges hook in `AccountDbContext`. The hook allocates an address when a user is created, follows username changes (Policy A, D-01), and always retires addresses on deletion (D-03). It adds no lookup service and no HTTP surface: plan 04-02 adds those.

Purpose: The hook is the only codegen-free interception point, because generated Wolverine handlers `new` repositories directly. The Account-specific risks here are:
- change detection (`DbSet.Update` marks every property modified, research Pitfall 1);
- hook re-entry during the demotion flush (Pitfall 2);
- own-suffix and case-only no-ops (Pitfall 3);
- tombstone privacy (Pitfall 5).

This plan locks each of them with tests that would fail on the regression.

Output:
- 1 domain type and 1 options class
- 1 EF configuration and 1 generated migration
- the transaction helper and the writer
- the DbContext override and the DI flag binding
- 3 new test files
</objective>
