# Публичный профиль

Все маршруты вызываются через Gateway. Имя на экране — `userName`. Email, телефон
и город публично не возвращаются. Аватар и описание необязательны. Неизвестный,
заблокированный или удалённый профиль возвращает 404. Для разрешения slug требуется
`PublicAddresses__Enabled` в Account и существующий backfill публичных адресов.

## Профиль и счётчики

`GET /api/Users/{slug}` доступен гостю; с JWT учитывает текущего зрителя.
Оболочка `{ data, address }` сохранена. В `data` добавлены `addedRoastersCount`,
`followersCount`, `isFollowing`.

| Подпись | Поле | Смысл |
| --- | --- | --- |
| Чекины | `checkInCount` | Прежний накопительный счётчик созданных чекинов |
| Кофейни | `addedShopsCount` | Прежний счётчик одобренных добавлений кофеен |
| Обжарщики | `addedRoastersCount` | Одобренные добавления обжарщиков, один раз на заявку |
| Подписчики | `followersCount` | Подписчики с доступным публичным профилем |

Первые два счётчика сохраняют прежний смысл и не обязаны совпадать с количеством
публичных чекинов. `isFollowing` показывает подписку текущего зрителя; для гостя
и собственного профиля это `false`. `GET /api/Users/me` также получает
`addedRoastersCount` и `followersCount`; его личные поля остаются личными.
Ответы профиля и новых разделов используют `Cache-Control: no-store`.

## Подписки

| Метод и маршрут | Доступ | Ответ |
| --- | --- | --- |
| `PUT /api/Users/{slug}/follow` | JWT | `{ followersCount, isFollowing }` |
| `DELETE /api/Users/{slug}/follow` | JWT | `{ followersCount, isFollowing }` |
| `GET /api/Users/{slug}/followers?page=1&pageSize=20` | Гость | `{ items, totalCount, page, pageSize }` |
| `GET /api/Users/{slug}/following?page=1&pageSize=20` | Гость | `{ items, totalCount, page, pageSize }` |

Повторные PUT/DELETE идемпотентны. Подписка на себя возвращает 400. `page` —
1–10000, `pageSize` — 1–100; неверные значения возвращают 400. Элемент списка:
`{ userName, avatarUrl, address }`, без контактов и внутренних ID. Недоступные
пользователи исключаются из списков и счётчика. Сначала идут новые подписки,
при одинаковом времени применяется стабильный порядок по пользователю.

Новые follow endpoints возвращают DTO напрямую. Остальные endpoints сохраняют
свои оболочки. Лента подписок не добавляется; общая лента и фильтр автора работают
как раньше.

## Любимые

`GET /api/v1/profiles/{authorSlug}/favorites` возвращает публичное избранное
владельца профиля. **Все сохранённые избранные объекты видны в этом разделе**;
отдельной настройки приватности избранного нет.

Собственные `GET /api/v1/favorites` и `PUT/DELETE /api/v1/favorites/{kind}/{slug}`
требуют JWT; пользователь определяется сервером. Чтение возвращает
`Response<DiscoveryFavoriteItem[]>`, изменение — 204.

Поддерживаются `kind=coffee_shop`, `roaster`, `drink`. Для напитка используется
стабильный slug каталога напитков, включая `_` (например `matcha_latte`).
Неверный kind/slug — 400, неизвестная или недоступная сущность — 404.

Карточка содержит `kind`, `createdAtUtc`, `name`, `coverPhoto` и ссылку:

- Кофейня/обжарщик: существующий `address`, `drink=null`.
- Напиток: `drink: { slug }`, `address=null`; фиктивный URL страницы не создаётся.
- `coverPhoto` может быть `null`, в том числе у напитков; клиент показывает заглушку.

Скрытые/закрытые кофейни и неактивные напитки исключаются из выдачи. Сначала идут
последние добавленные объекты. Старое избранное сохраняется.

## Публичные чекины и календарь

Лента автора уже доступна через `GET /api/v1/check-ins?authorSlug={slug}`
с `pageSize` и `cursor`; лента публикаций — `/api/v1/feed?authorSlug={slug}`.
Отдельной сущности или счётчика отзывов нет.

`GET /api/v1/profiles/{authorSlug}/activity?year=2026&month=10&timeZone=Europe/Minsk`
возвращает `Response<ProfileActivityDto>`. Пример `data` (показаны первые два дня):

```json
{
  "year": 2026,
  "month": 10,
  "timeZone": "Europe/Minsk",
  "activeDays": 1,
  "totalCheckIns": 2,
  "days": [
    { "date": "2026-10-01", "checkInCount": 2 },
    { "date": "2026-10-02", "checkInCount": 0 }
  ]
}
```

Фактический ответ включает все дни месяца. `year` (2000–2100) и `month` (1–12)
обязательны; `timeZone` по умолчанию `UTC`. Неверный период или зона возвращает 400.
Границы месяца и группировка по `visitedAt` учитывают часовой пояс и летнее время.
Применяются правила публичной ленты: актуальные одобренные публичные чекины,
включая домашние и чекины доступных кофеен. Пустой месяц возвращает нули.

## Миграции и первоначальное заполнение

Account получает таблицы `UserFollows`, `UserRoasterCredits` и столбец
`Users.AddedRoastersCount`. Shops получает ограничение допустимых видов избранного.
Новый Account-обработчик существующего `ModerationRoasterApprovedEvent` защищён
от повторного начисления уникальным ID заявки в таблице `UserRoasterCredits`.

После миграций и до запуска сервисов:

```bash
# Production: читает deploy/.env, использует Compose PostgreSQL
bash dev/backfill-profile-roaster-counts.sh
# Локальная dev-инфраструктура
bash dev/backfill-profile-roaster-counts.sh --dev
```

Backfill переносит авторство одобренных заявок из Moderation и сверяет счётчик
с ledger. Анонимные заявки и отсутствующие/удалённые авторы пропускаются.
Повторный запуск безопасен. Сервисы-писатели должны быть остановлены.
`deploy.sh` и `ci-deploy.sh` уже вызывают его между миграциями и запуском приложений;
`dev/migrate-and-seed.sh` также включает этот шаг. Исторические миграции сохранены.
