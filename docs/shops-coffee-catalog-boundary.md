# CoffeeCatalog: доменная модель и прикладные сценарии (P19/P20)

`CoffeeProduct` теперь не отдаёт изменяемые ссылки на массивы содержимого, классификации и защищённых полей: входящие и исходящие массивы копируются. `Countries` и `Sources` доступны для чтения, а изменение состава стран выполняет `ReplaceCountries`/`ApplyImportedCountries`, источника — `AttachSource`. У `CoffeeProductSource` предупреждения также копируются, а состав вариантов и фотографий меняется методами `AttachVariant`, `AttachPhoto`, `RemovePhotosExcept`. Эти операции увеличивают `Version` родительского продукта. Импорт стран проверяет защиту ручного поля внутри продукта. Импорт, меняющий только наличие источника и доступность вариантов, увеличивает `Version` продукта, чтобы конкурентная административная правка обнаруживала конфликт по EF concurrency token.

Обратная совместимость EF проверена без миграции: backing fields для массивов и дочерних коллекций распознаны, сохранение и чтение в новых контекстах работает, `HasPendingModelChanges()` ложно. Контракт HTTP и структура таблиц не менялись.

Дочерние объекты `CoffeeProductSource`, `CoffeeVariant`, `CoffeeProductPhoto` теперь имеют закрытые setters и EF-конструкторы. Метаданные источника, цена/доступность предложения и данные фото изменяются доменными операциями с повышением версии продукта. Идентичность источника/варианта и parent binding нельзя переписать; перенос варианта/фото в другой агрегат отвергается. `SetBrewPurpose` сам повышает версию при реальном изменении и сохраняет ручную защиту при импорте; прежнее дополнительное повышение версии в Persistence удалено. Невалидная цена, валюта, объём или поздняя коллекция content отвергаются до мутации. Схема PostgreSQL не менялась, EF snapshot совпадает с моделью. Шесть новых PostgreSQL сценариев проверяют конфликт source/offer/photo с ручной правкой в обоих порядках и отсутствие частичных записей; CI требует их выполнение без skips. Бизнес-координация `CoffeeCatalogStore` остаётся частью P20.

`CoffeeImportRun` тоже закрывает setters. Конструктор фиксирует идентичность, `MarkFailed`/`MarkApplied` определяют переходы и проверяют timestamp/counters; применённый run нельзя превратить в failed или переписать повтором с тем же payload. Четыре доменных теста защищают failure→retry, неизменность применённого run и запрет другого payload под прежним ID.

Все клиенты переведены на узкие порты: `IPublicCoffeeCatalogReader`, `IAdminCoffeeCatalogReader`, `ICoffeeProductWriter`, `ICoffeeCatalogTagWriter`, `ICoffeeImportWriter`. Универсальный `ICoffeeCatalogStore` удалён. Публичные handlers обжарщиков используют только public reader; admin controller получает только admin reader и dispatches команды через Wolverine. Read-порты делят один scoped экземпляр `CoffeeCatalogStore`; production writer-порты зарегистрированы как `CoffeeProductWriter`, `CoffeeCatalogTagWriter`, `CoffeeImportService` из Application. SQL-адаптеры `CoffeeProductStorage`, `CoffeeCatalogTagStorage`, `CoffeeImportStorage` получают тот же scoped DbContext. Старые concrete store методы оставлены тонкими compatibility delegates для существующих fixtures; production DI их не использует для записи. Architecture tests запрещают write/import методы в reader-портах и решения о ручном приоритете/import lifecycle в Persistence.

Координация create/edit/archive, назначения тегов, snapshot identity/order, coverage, происхождения стран, protected fields/photos, классификации и failure reporting находится в Application/Domain. SQL projections остаются в Persistence. `ApplyManualEdit` проверяет весь пакет до изменения первого поля; поздняя ошибка protected field/country не оставляет изменённые name/status/version даже в памяти. Snapshot storage сохраняет прежнюю advisory-lock транзакцию и отдельную failed-run запись после rollback. Перенос нормализатора и exception в Application не меняет HTTP error key/status, routes или формы DTO; public message/consumer types не переименованы.

Подтверждение P19 и предшествующего writer-среза: [CI commit 88d677f3](https://github.com/CoffeePeek/coffeepeek-backend/actions/runs/37900845897) выполнил 35 direct-write и шесть child/manual concurrency сценариев на PostgreSQL 17 без skips. После P20 direct-write fixture использует production `AddCoffeeCatalogModule`; следующий CI повторяет transaction checks с новыми implementations. Все 15 сохранённых catalog snapshots и полный локальный backend regression проходят.

Фабрики writer-портов скрывали DbContext от Wolverine. Явная зависимость handlers от существующего `IUnitOfWork` теперь включает EF/outbox middleware для create/edit/archive кофе и create/edit/set тегов. Сохранившиеся `SaveChangesAsync` — flush внутри общей транзакции для readback, а commit выполняется до ответа. Generated adapters получены штатным `codegen write`. Двенадцать PostgreSQL сценариев проверяют реальный commit, отдельную сессию до commit, rollback после late failure и повтор назначения тегов; обязательный CI gate не допускает skips. Snapshot-import пока сохраняет собственную границу транзакции и отдельную запись failed run.
