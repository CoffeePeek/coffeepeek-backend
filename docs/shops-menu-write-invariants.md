# Согласованность ручного меню (P13–P14)

Одна кофейня имеет не более одного меню, а один напиток — не более одной позиции в нём. Запрос ручной правки предварительно проверяется целиком: неизвестный или повторённый напиток, недопустимый enum и некорректная цена/объём дают отказ без записи. Присутствующая позиция требует строго положительную цену и объём; отсутствующая либо неизвестная — оба значения `NULL`. Создание и обновление повышают `ShopMenu.InputRevision` один раз за весь пакет, в том числе пустой, чтобы устаревший OCR не применился после ручной операции.

Существующее меню обновляется SQL upsert в одной транзакции с условным повышением ревизии. Конфликт ревизии даёт 409, а не повторный запуск устаревшей команды. После SQL путь перечитывает позиции в EF context, чтобы ответ и последующий код не использовали старый tracking. Конкурентное создание второго меню блокируется уникальным индексом `ShopMenus.CoffeeShopId` и отображается как 409.

Миграция `20261008094000_EnforceShopMenuItemValues` добавляет PostgreSQL `CHECK` для тех же комбинаций доступности, цены и объёма. По согласованной политике исправления старые некорректные позиции сохраняются, но переводятся в `Unknown` с `Price=NULL` и `VolumeMl=NULL`. Корректные позиции не меняются. Исправление и установка CHECK выполняются в одной транзакции при остановленных писателях; сами позиции и их ID не удаляются. Операционный запрос до миграции:

```sql
SELECT "Id", "ShopMenuId", "DrinkDefinitionId", "Availability", "Price", "VolumeMl"
FROM "ShopMenuItems"
WHERE NOT (
    "Availability" IN (0, 1, 2)
    AND (("Availability" = 1 AND "Price" IS NOT NULL AND "Price" > 0
          AND "VolumeMl" IS NOT NULL AND "VolumeMl" > 0)
         OR ("Availability" <> 1 AND "Price" IS NULL AND "VolumeMl" IS NULL))
);
```

Локально проверяются доменный batch и SQL миграции. Поведение ограничения, обновление EF tracking и конкуренция создания проверяются live PostgreSQL тестом `ShopMenuManualWriteLiveTests` в обязательном CI gate. До его фактического прохождения это доказательство остаётся неполным. Сравнение всех комбинаций EF и SQL записи, включая сбои между SQL и commit, остаётся открытой частью P14/P31.
