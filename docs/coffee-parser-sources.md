## Какие части действительно общие

Общий транспорт уже обеспечивает ограничение доменов и редиректов, паузу между запросами, повтор временных сетевых ошибок, ограничение размера ответа и проверяемый HTTP-кеш. Общий контракт хранит внешние ID, цену/валюту, доступность, страны с основанием определения и замечания. Джоба сохраняет результаты каждого источника отдельно и заменяет JSON только после успешного завершения его обхода; сбой одного сайта сохраняет прежний снимок этого сайта и даёт ненулевой код завершения.

Tilda переиспользует один обход API для Spiritus, Совы и Single Step. Разбор SKU различается: `Тип/Вес`, `Вид фасовки`, либо строки `0,25 кг=28` в свойствах. WooCommerce переиспользует один сборщик для KCR и Ideal: текущая цена делится на `10 ** currency_minor_unit`, вариации читаются с нативными ID и проверяется их родитель. Это публичный [Store API](https://developer.woocommerce.com/docs/apis/store-api/resources-endpoints/products); административные ключи не нужны.

Sorso, Sense и Marconi переиспользуют разбор деревьев SKU и обход страниц. Их селекторы, структура шаблона JSON и URL выбора варианта различаются. В HTML присутствуют цены всех SKU, включая невыбранные: цена берётся из видимого блока выбранного варианта, затем проверяется его ID. Один общий CSS-селектор для всех Bitrix-сайтов не подходит.

Tasty Coffee, Сварщица, Daloni и Blaser имеют отдельные извлекатели данных. Для Mcoffee используется наблюдаемый запрос `/products/get-variant` с `view=card`: он возвращает HTML выбранной фасовки. Транспорт разрешает POST только к этому запросу чтения; запросы добавления в корзину, оформления заказа и личного кабинета не выполняются.

## Расхождения, которые влияют на модель

- **Источник продажи и обжарщик различаются.** Сова продаёт KOF и Kanga; сохранены `sellerName` и реальный `roasterName`. Одному источнику нельзя безусловно назначать одного обжарщика всем карточкам. Название домена Mcoffee также не заменяет бренд Manufactura.
- **Вес не определяет SKU.** У Сварщицы один родительский ID может иметь одинаковую фасовку под фильтр и эспрессо. Назначение сохранено в `sourceAttributes.roastPurpose`; все нативные SKU остаются отдельными. Повторные URL в нескольких разделах объединяются по родительскому ID с проверкой совпадения вариантов, а ссылки сохраняются как `sourceAliases`.
- **Нативного SKU может не быть.** У Single Step фасовки — строки свойств с абсолютными ценами; у Tasty Coffee — варианты ценовой опции. Составные ключи помечены `identityKind=option_combination`. Их изменение требует проверки сопоставления; выдавать такие ключи за нативные SKU нельзя.
- **Категория не гарантирует формат и полноту.** В категории зерна KCR есть дрипы и нет двух продающихся сортов. Сбор теперь идёт по общему разделу кофе из 30 карточек, затем исключаются 10 дрипов и набор. У Совы и Single Step в исходной выдаче тоже есть другие форматы.
- **Цена до скидки не является статусом наличия.** Поле `without` Tasty Coffee — зачёркнутая цена. Цена фасовки равна текущей базовой цене плюс ценовая поправка опции; скидка второй раз не вычитается. Возможность покупки проверяется по кнопке карточки. Этот случай входит в runnable-проверку.
- **Валюта обязательна.** RUB и BYN сохраняются отдельно. Цена за килограмм не вычисляется при неизвестном весе; конвертация валют не производится.
- **Происхождение не ограничивается исходными 30 странами.** Обнаружена Малайзия (`MY`, [UNGEGN](https://ungegn.un.org/dashboard/countries/details?id=458)); алиас добавлен в разбор. Справочник приложения должен пополняться проверенными кодами перед применением таких записей. «Конго Kivu Lake 3» у Daloni остаётся неоднозначным: пользовательский выбор `CG` для исходного справочника не доказывает происхождение внешней карточки.

## Полнота и известные ограничения

У Tasty Coffee сверены все 162 исходные карточки на 14 страницах; 90 — зерно, 72 — другие форматы. Сова сверена с 23 карточками API, Single Step — с 45, KCR — с 30, Ideal — с 8. WooCommerce дополнительно проверяет счётчики страниц и элементов в заголовках, совпадение списка вариаций и их родительских ID.

У HTML-каталогов независимый счётчик отсутствует: `expectedProducts=null`. Обход завершается после всех найденных страниц/ссылок меню; `complete=true` означает успешный обход указанных разделов, а не внешнюю гарантию размера всего ассортимента. У Сварщицы пройдены 3 раздела зерна, 73 ссылки карточек свелись к 61 родительскому ID. У Mcoffee пройдены 4 страницы с 30 строками и 26 родительскими ID; повторные строки проверены по выбранному SKU, 11 недоступных товаров подтверждены `OutOfStock` в карточке. У Daloni пройдены моносорта, купажи и зелёный кофе: 69 исходных карточек, исключены 3 набора и 2 товара «Ожидаем». У Blaser просмотрены все 15 товаров меню; Leggero и Forte продаются только молотыми.

## Повторная проверка всех 15 источников, 7 октября 2026

Все 15 сборщиков успешно повторены **без сети** на одном наборе захваченных ответов: **450 товаров и 893 варианта**. Исходная версия успешно разбирала 14 этих же каталогов; после исправлений полностью совпадают `sourceProductId`, URL, доступность товара и все варианты с ID, весом, ценой, валютой и доступностью. River отдельно воспроизводил ошибку на опубликованном остатке `4 шт`; единица теперь распознаётся только в его собственном формате.

Предупреждения `detail_properties_not_collected` **282 → 0** исчезли после чтения конкретных разделов карточки. Количество в таблице отражает текущий захват; оно отличается от исторического экспорта 5 октября из-за изменений ассортимента. Полные новые снимки и HTTP-кеш не включаются в Git. В `dev/coffee-import/fixtures/` сохранены небольшие продуктовые фрагменты для регрессии; проверка исходной версии на том же фрагменте Совы воспроизводит пропущенную оценку `83`.

При захвате Manufactura выявлен отдельный транспортный сбой: два несжатых ответа завершились `IncompleteRead`, два запроса gzip вернули полный HTML. Транспорт явно запрашивает уже поддерживаемый gzip; ограничение размера после распаковки, повтор ошибок и запрет частичных снимков сохранены. Все дальнейшие проверки выполнены offline. Вес трёх Daloni Vintage Collection по-прежнему не опубликован в прочитанных данных: сохраняется `weightGrams=null` и предупреждение. У Сварщицы и Tasty сохраняется `availability_reported_at_product_level`.

Перед обычным обновлением существующих импортов нужно развернуть исправленные сборщики и Shops, применить миграцию `20261007065353_AddDominicanCoffeeOrigin`, затем выполнить свежий `import_coffees.py --push` по настроенной процедуре из README. Старые файловые снимки сами не получают новых характеристик. Эта проверка не применяла импорт к production.


Для команды Shops отсутствие товара в HTML-снимке нельзя использовать как безусловное массовое снятие с продажи. Резкое уменьшение каталога и отсутствие независимого счётчика требуют отдельной проверки перед такими обновлениями. Ручные описания и подтверждённые страны не должны перезаписываться неполными полями.

## Страна из названия и кофеин, 8 октября 2026

Однозначная единственная страна из названия кофе без признака смеси принимается при импорте без ручного подтверждения. Основание `name` сохраняется; приоритет явно заданных свойств и утверждений о составе не меняется. Смеси, несколько стран, неоднозначное «Конго», отсутствующая страна и защищённые вручную страны сохраняют прежнюю обработку.

Повторный разбор всех 15 прежних снимков без сети подтвердил неизменность 450 товаров, 893 вариантов и данных происхождения. Предупреждений `origin_extracted_from_name` стало **263 → 2**: у 261 однозначной карточки они убраны, две карточки смесей сохранены для проверки. Исходная страна остаётся указана у 412 товаров; отсутствие страны у 38 товаров и остальные существенные предупреждения не скрываются.

Кофеин при импорте по умолчанию обычный (`regular`). Сервер сначала проверяет признаки в характеристиках, затем название и описание товара на декаф/лоукаф. Название декафа имеет приоритет над общим текстом о линейке декафов и лоукафов; `UNDECAF`, отрицание «не декаф», рекомендации другого кофе и неопределённый состав Cleanskin не являются подтверждением. Защищённая вручную классификация кофеина сохраняется. Новая миграция для этих правил не нужна; существующие карточки обновятся после свежего импорта.

## Проверка и запуск

```powershell
python -X utf8 -m unittest discover -s dev/coffee-import -p 'test_*.py'
python -X utf8 dev/coffee-import/import_coffees.py --offline
python -X utf8 dev/coffee-import/import_coffees.py --source shop.tastycoffee.ru --source 'сова.бел'
```

Первый запуск проверяет 43 теста, включая регрессии на захваченных характеристиках всех платформ. Второй повторяет все 15 сборщиков из локального HTTP-кеша; кеш исключён из Git. Третий обновляет выбранные сайты из сети; без `--source` обновляются все зарегистрированные сайты. Расписание — существующий systemd timer раз в сутки, установка описана в `dev/coffee-import/README.md`.

Модель и транзакционный импорт описаны в docs/coffee-catalog-plan.md и docs/coffee-import-deployment.md.
