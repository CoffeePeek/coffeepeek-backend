# Основное оборудование кофейни (P11)

`IsPrimary` относится к назначению оборудования конкретной кофейне (`ShopEquipment`), а не к общей записи каталога `Equipment`. Для одной кофейни допускается не более одного основного устройства в каждой категории; в разных категориях выбор независим. Один и тот же каталоговый экземпляр может быть основным в одной кофейне и обычным в другой.

Администратор выбирает список основных устройств через `PUT /api/admin/shops/{id}/primary-equipment`, владелец — через `PUT /api/owner/coffee-shops/{id}/primary-equipment`; тело: `{ "primaryEquipmentIds": ["<guid>"] }`. Пустой список снимает все отметки. Каждый ID должен уже входить в набор оборудования этой кофейни. Ответ содержит `primaryEquipmentIds`. Старые операции изменения профиля без этого поля сохраняют отметки у оставшегося оборудования и удаляют отметки вместе с удалёнными назначениями.

Миграция `20261008092000_AssignShopEquipmentPrimary` переносит категорию в таблицу `CoffeeShopEquipments`, создаёт составной FK на `Equipments(Id, CategoryId)` и частичный уникальный индекс `(CoffeeShopId, CategoryId) WHERE IsPrimary`. Категория назначенного оборудования больше не может быть изменена, пока есть ссылки; конфликт БД отображается как HTTP 409. При смене основного устройства в категории старое назначение очищается перед сохранением нового в одной Wolverine/EF-транзакции: иначе промежуточный `UPDATE` мог бы нарушить уникальный индекс.

Старый каталоговый `Equipments.IsPrimary` не показывает выбор каждой кофейни. Миграция сохраняет эту колонку без отображения в новой EF-модели: старый бинарник может продолжать её читать и писать в переходное окно, а новое оборудование получает DB default `false`. Все существующие назначения начинают с собственным `IsPrimary = false`; старый флаг автоматически не трактуется как выбор владельца. Триггер временно заполняет `CoffeeShopEquipments.CategoryId` для вставок старого бинарника, который знает только два прежних FK. Для аудита после миграции:

```sql
SELECT e."Id", e."Name", e."IsPrimary" AS "LegacyIsPrimaryHint", ce."CoffeeShopId"
FROM "Equipments" AS e
LEFT JOIN "CoffeeShopEquipments" AS ce ON ce."EquipmentId" = e."Id"
WHERE e."IsPrimary" = TRUE
ORDER BY e."Id", ce."CoffeeShopId";
```

Проверки: доменные тесты для независимости кофейн, сохранения выбора и ограничения категории; тест миграционного SQL; live PostgreSQL тест `ShopEquipmentLiveTests` для сохранения/чтения, переключения выбора и уникального индекса. Live-тест требует `COFFEEPEEK_LIVE_PG` и выполняется в PostgreSQL CI gate. Локально без PostgreSQL он пропускается.
